# Content → Commerce → Evidence Loop

The Observatory should not create separate work for every platform.

One real experiment or digital prototype should produce multiple descendants.

## Source event

Examples:
- a mechanism is CAD checked;
- a prototype is printed;
- a measurement changes the conclusion;
- a new open-source tool unlocks an experiment;
- a current paper changes an Observatory question;
- a digital-first simulation makes an invisible phenomenon visible.

## Descendants

From one good source event create, as appropriate:

1. **Evidence record** — raw result, limits, failure.
2. **Website update** — Living Plate / Workshop / research note.
3. **YouTube** — longer build / question / measurement story.
4. **Short video** — one visual hook + one measured result.
5. **LinkedIn** — verified external work or exact status of own work.
6. **Carousel / still** — visual explanation.
7. **Game interaction** — when the phenomenon can be made playable.
8. **Digital download** — simulation, data, CAD, guide.
9. **Physical product** — only after physical evidence earns it.
10. **School / educator pack** — question, experiment, data, explanation.

## Media grammar

```
QUESTION
→ PREDICTION
→ MAKE / SIMULATE
→ TEST
→ RESULT
→ FAILURE / SURPRISE
→ CHANGE ONE THING
→ RETEST
```

This is stronger than generic “look what AI made” content.

## Digital-first rule

Digital prototypes are valuable and publishable when labelled honestly:

- CONCEPT VISUALISATION
- DIGITAL MODEL
- SIMULATION
- CAD CHECKED

They do not become BUILT or TESTED until physical evidence exists.

## Commercial rule

```
ATTENTION
→ CURIOSITY
→ TRUST
→ USEFUL OBJECT / EXPERIENCE
→ PURCHASE
→ USER FEEDBACK
→ IMPROVEMENT
```

Do not spend money to scale something that has not earned initial demand.

## Reuse rule

> ONE GOOD PIECE OF WORK SHOULD HAVE MANY DESCENDANTS, NOT MANY DISCONNECTED POSTS.
