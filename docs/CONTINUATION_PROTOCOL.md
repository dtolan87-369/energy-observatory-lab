# Continuation Protocol

The Energy Observatory is a living system. New chats, tools and agents must continue it rather than restart it.

## After every substantial pass

Update only what materially changed:

1. **Current state** — what is now true?
2. **Evidence state** — what moved on the evidence ladder?
3. **Decision state** — what was selected, rejected, deferred or left open?
4. **Next action** — what is the smallest useful next step?
5. **Reusable rule** — did a general principle emerge?
6. **Structured pipeline** — add/update the relevant Airtable candidate if the item may become a tool, experiment, game or product.
7. **Repository** — commit code, briefs, schemas or templates that improve repeatability.
8. **START HERE** — update the rolling continuation only for substantial programme-level changes.

## Do not

- duplicate the archive into this repo;
- silently renumber Observatory objects;
- convert candidate dimensions into standards without evidence;
- treat generated material as build/test evidence;
- recreate tools that an appropriate open-source component already solves well.

## Handoff format

Every active object should be reducible to:

```
OBJECT
PURPOSE
CURRENT STATUS
SOURCE / PROVENANCE
WHAT IS VERIFIED
WHAT IS NOT VERIFIED
OPEN RISKS
NEXT SMALLEST TEST
RELATED FILES / REPOS
```

## Guiding rule

> EACH PASS SHOULD LEAVE THE OBSERVATORY EASIER TO CONTINUE THAN IT FOUND IT.
